## Known Issues
- Legal mismatch with Ozone's live Terms of Service regarding age requirements and public upload availability.
- Difficulty obtaining creator information from social media platforms due to platform structure differences and access limitations.
- Low email yield (~4 valid emails from 120 profiles); Instagram/Meta profiles lacking API access require manual review.
- Reddit blocks headless browsers aggressively — karma and bio fields may be empty when the block page is served. The requests-first fallback returns None when no OG data is found, triggering Playwright, but block detection may still result in empty fields.
- Creator Intel CRM contained 1,038 empty rows among 2,108 total — cleaned to 1,070 valid creators. Re-scraping workflow includes suspicious-value detection which caught follower-count and FeedURL anomalies in initial testing.
- Google Sheets HTTP 429 rate limiting causes partial syncs to stop mid-write (observed at row 705 → Tags column); scraper works correctly but the Sheets write layer is the bottleneck.
- Creator retry/cooldown mechanism missing — failed creators may become permanently excluded from rescue batches since selection prioritizes "never successfully rescraped" entries.
- Vimeo is selector-enabled but not connected to production rescrape dispatch — Vimeo creators in CRM will never be selected for rescraping.
- Facebook records with post/video URLs (instead of profile/page URLs) cannot have follower counts extracted — future enhancement needed to resolve post/video URLs to profiles.
- Vimeo Playwright async integration broken — VIMEO_RUNTIME_ERROR occurs because Playwright Sync API is being executed inside an asyncio event loop. Partial sync safety is verified; success-write path blocked until async issue is fixed.
